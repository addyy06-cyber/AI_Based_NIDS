    Limitations

    • One training dataset. The model learned from CICIDS2017 only (one test network, one week, 10 attack types plus normal traffic). It has never seen other networks, newer attacks, or Heartbleed and Infiltration.
    • Inputs must match the training features. The file needs the 69 flow features produced by a CICFlowMeter-style extractor. Raw packet captures cannot be scored directly.
    • Estimated performance is optimistic. In blocked cross-validation the macro-F1 was about 0.95 (worst fold about 0.90). The settings were chosen on those same folds, and the test was never run on a different network.
    • False alarms. About 0.2% of normal flows were flagged in testing (0.36% in the worst fold). On a busy network that still means many false alerts per day.
    • Alert types differ in reliability. Roughly 3 in 8 Bot alerts were wrong in testing, and the slow DoS types (slowloris, Slowhttptest) were missed about 15% of the time.
    • "Not scored" does not mean safe. Rows with missing, infinite or invalid values are listed but were not judged.
    • Scores are not probabilities. Confidence is the share of trees voting for the predicted type.
    • Detection only. The system reports suspicious flows. It does not block anything, and results are model estimates, not proof of malicious activity.
    • Prototype. This is a coursework project and not a production security tool.
